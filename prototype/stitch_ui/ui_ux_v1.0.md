# 交易系统前端 UI / UX 全量重构设计方案 V1.0

> 目标：基于现有后端已经形成的 Trade 生命周期模型，重新设计交易系统前端。
>
> 本文不讨论“如何在现有页面上小修小补”，而是把交易系统前端作为一个全新版本重新规划。
>
> 核心原则：**所有交易相关页面必须围绕 Trade 串联，而不是把交易计划、执行、订单、持仓做成互相独立的孤岛。**

---

# 1. 核心业务模型

前端必须统一围绕以下关系呈现：

```text
Trade
│
├─ TradePlan
│   ├─ OPEN
│   ├─ ADD
│   ├─ REDUCE
│   └─ CLOSE
│
├─ ExecutionPlan
├─ Order
├─ Fill
├─ TradeLeg
├─ TradePositionState
├─ PositionRiskHistory
└─ ExitRule
```

用户必须能从任何一个页面理解：

> 我现在看到的这个订单、执行计划、持仓、风险，属于哪一笔 Trade、哪一个动作。

---

# 2. 用户心智模型

整个交易系统只围绕三个问题：

```text
1. 我准备做什么？
2. 这笔交易现在进行到哪里？
3. 下一步我要做什么？
```

主流程：

```text
发现股票
↓
创建 Trade
↓
OPEN 建仓计划
↓
确认计划
↓
创建 ExecutionPlan
↓
订单 / 成交
↓
Trade ACTIVE
↓
持仓管理
├─ ADD
├─ REDUCE
├─ 调整风险参考
└─ CLOSE
↓
持仓归零
↓
Trade CLOSED
↓
复盘 / Playbook统计
```

# 3. 顶层导航

建议交易系统仍然只保留 5 个二级入口：

```text
交易总览
交易
交易执行
订单
持仓
```

说明：

- 原“交易计划”改名为 **交易**。
- 因为新页面不再只是计划列表，而是整个 Trade 生命周期的主入口。
- Trade Detail 是“交易”页面内部的核心详情页，不单独占二级导航。
- 交易设置仍通过 Header 设置图标打开，不作为二级导航。

# 5. 页面一：交易总览

## 5.1 页面目标

让用户一进入交易系统就知道：

```text
账户现在是什么状态？
有哪些 Trade 正在进行？
风险集中在哪里？
有什么需要处理？
```

## 5.2 顶部账户摘要

第一行 4 个核心卡片：

```text
账户净资产
可用现金
当前总仓位
账户当前总计划风险
```

第二行可选：

```text
今日盈亏
累计盈亏
持仓市值
活动 Trade 数
```

## 5.3 风险概览

显示：

```text
账户当前总计划风险
账户最大风险预算（如未来配置）
当前总仓位
账户最大总仓位
可用现金
```

如果部分 Trade 没有有效风险参考：

```text
部分 Trade 尚未设置有效风险参考，账户总计划风险可能低估。
```

不要静默显示错误的 0。

## 5.4 待处理事项

独立卡片：

```text
待执行 TradePlan
待确认 ExecutionPlan
部分成交
CLOSE 受 T+1 限制
风险参考需要更新
ExitRule 已触发但待人工确认
券商断线
```

示例：

```text
3 项待处理

安硕信息
ADD #1 已确认，尚未创建执行计划

XXX
CLOSE 当前剩余 200 股 T+1 待卖

YYY
风险参考已长时间未更新
```

每条点击进入对应 Trade。

## 5.5 活动 Trade

表格：

| 股票 | 类型 | 状态 | 当前持仓 | 资金仓位 | 浮动盈亏 | 本金计划风险 | 利润回吐风险 | 最近动作 | 操作 |
|---|---|---|---:|---:|---:|---:|---:|---|---|
| 安硕信息 | 趋势 | ACTIVE | 500股 | 15.2% | +¥1,250 | ¥320 / 0.32% | ¥780 | ADD #1 | 查看 |

点击整行进入 Trade Detail。

操作列只保留“查看”，不要在总览塞过多动作。

## 5.6 最近动作

展示最近：

```text
OPEN
ADD
REDUCE
CLOSE
风险参考调整
订单成交
```

例如：

```text
10:31 安硕信息 ADD #1 成交 200股 @31.12
09:48 XXX 风险参考 12.30 → 12.85
昨日 YYY REDUCE 30% 已完成
```

# 6. 页面二：交易（Trade List）

## 6.1 页面目标

这是所有 Trade 的主入口，不是“计划列表”。

## 6.2 顶部

```text
标题：交易
说明：管理从建仓到清仓的完整交易生命周期
```

右侧：

```text
[创建新交易]
```

## 6.3 筛选

状态：

```text
全部
计划中
进行中
清仓中
已结束
已取消
```

交易类型：

```text
全部 / 趋势 / 反弹 / 固定目标 / 自定义
```

其他：

```text
股票搜索
Playbook筛选
日期范围
```

## 6.4 默认 Trade 表格

一行一个 Trade：

| 股票 | 类型 | 状态 | 当前持仓 | 当前价格 | 浮动盈亏 | 本金风险 | 回吐风险 | 最近动作 | 创建时间 | 操作 |
|---|---|---|---:|---:|---:|---:|---:|---|---|---|

状态翻译：

```text
PLANNED → 计划中
ACTIVE → 进行中
CLOSING → 清仓中
CLOSED → 已结束
CANCELLED → 已取消
```

## 6.5 行展开

可展开查看：

```text
OPEN #1
ADD #1
ADD #2
REDUCE #1
CLOSE #1
```

但默认主视图始终以 Trade 为单位。

# 7. 页面三：Trade Detail（核心页面）

> 这是整个新前端最重要的页面。

## 7.1 顶部 Header

显示：

```text
安硕信息 300380
趋势交易
Playbook：xxxx（如有）
状态：进行中
```

ACTIVE 时右侧：

```text
[加仓]
[减仓]
[清仓]
[调整风险参考]
```

PLANNED：

```text
[编辑建仓计划]
[取消交易]
```

CLOSED：

```text
[查看交易结果]
```

## 7.2 持仓摘要

```text
当前持仓
可卖数量
平均成本
当前价格
资金仓位
浮动盈亏
```

例如：

```text
当前持仓        500股
可卖            300股
平均成本        ¥29.85
当前价格        ¥32.10
资金仓位        16.05%
浮动盈亏        +¥1,125 / +7.54%
```

## 7.3 风险面板

显示：

```text
Trade风险预算
当前本金计划风险
当前利润回吐风险
剩余风险容量
当前整体风险参考
```

例如：

```text
Trade风险预算       ¥800 / 0.80%
本金计划风险         ¥320 / 0.32%
利润回吐风险         ¥780
剩余风险容量         ¥480
当前风险参考         ¥30.54
```

按钮：

```text
[查看计算]
[调整风险参考]
```

## 7.4 风险计算展开

点击“查看计算”：

```text
OPEN leg
数量：300
成本：29.47
风险参考：30.54
到风险参考 PnL：+321

ADD #1
数量：200
成本：31.12
风险参考：30.54
到风险参考 PnL：-116

整笔 Trade：
计划退出 PnL：+205
本金计划风险：0
利润回吐风险：XXX
```

## 7.5 TradeLeg 区域

| Leg | 来源 | 剩余数量 | 平均成交价 | 当前风险参考 | 当前状态 |
|---|---|---:|---:|---:|---|
| OPEN | 二买建仓 | 300 | 29.47 | 28.60 | 持有 |
| ADD #1 | 突破确认 | 200 | 31.12 | 30.54 | 持有 |

说明：

> TradeLeg 用于内部风险归因，不代表券商账户中存在独立持仓。

## 7.6 Trade 时间线

```text
09-03 OPEN
计划 300股 @29.47
实际成交 300股 @29.52

09-08 ADD #1
计划 200股 @31.10
实际成交 200股 @31.12

09-12 风险参考调整
28.60 → 30.54

09-20 REDUCE #1
卖出 100股
待执行
```

节点展示：

```text
动作
计划状态
执行状态
订单状态
成交结果
理由
```

点击节点进入 Action Detail。

## 7.7 Exit Rules

例如：

```text
规则1
价格低于30.54
→ 提醒清仓
状态：启用

规则2
持有超过15个交易日
→ 提醒重新评估
状态：启用
```

按钮：

```text
[添加规则]
[编辑]
[停用]
```

V1 只做规则配置和提醒，不直接自动实盘卖出。

## 7.8 K线

提供：

```text
[查看K线]
```

K 线上未来标记：

```text
OPEN成交
ADD成交
REDUCE成交
CLOSE成交
风险参考历史
```

# 10. ADD 页面

## 10.1 入口

仅 ACTIVE Trade 可创建：

```text
Trade Detail → 加仓
持仓页 → 加仓
```

不要让用户从“创建新交易”里手动选 ADD。

## 10.2 顶部上下文

```text
安硕信息 300380
趋势交易
当前动作：加仓 #1
```

下面展示当前持仓：

```text
当前持仓
平均成本
当前价
资金仓位
浮动盈亏
当前本金风险
当前利润回吐风险
剩余 Trade 风险容量
```

## 10.3 输入字段

```text
加仓理由 *
参考加仓价 *
最高可接受加仓价 *
本次加仓风险参考价 *
本次风险预算 *
人工计划数量
加仓失败处理 *
计划有效期
```

## 10.4 加仓失败处理

```text
如果本次加仓逻辑失败：

○ 仅退出本次新增仓
○ 减仓到指定数量
○ 减仓到指定比例
○ 全部退出
○ 人工重新判断
```

根据选择显示对应参数。

## 10.5 加仓后风险管理

```text
加仓后如何管理风险？

○ 各 TradeLeg 保留独立风险参考
○ 整个 Trade 使用新的整体风险参考
○ 混合管理
```

如果选择整体：

```text
新的整体风险参考价
```

## 10.6 计算摘要

```text
系统建议加仓
加仓后总持仓
加仓后平均成本
加仓后资金仓位
```

风险：

```text
本次新增风险
加仓后整笔 Trade 本金风险
加仓后利润回吐风险
风险预算剩余
```

## 10.7 计算详情

折叠：

```text
风险计算
仓位限制
加仓前后对比
最高加仓价情景
账户依据
```

# 40. 最终设计标准

新前端成功的标准不是：

> 页面看起来更漂亮。

而是用户在任何时刻都能快速回答：

```text
这是什么 Trade？
现在持有多少？
我为什么持有？
当前风险是什么？
最近做了什么？
下一步能做什么？
这个动作会如何改变整个 Trade？
```

如果用户仍需要分别去：

```text
交易计划
交易执行
订单
持仓
```

几个页面拼凑信息，说明设计仍然失败。

真正的新前端应该做到：

> **Trade Detail 是业务中心；其他页面只是不同维度的工作台和查询页。**
