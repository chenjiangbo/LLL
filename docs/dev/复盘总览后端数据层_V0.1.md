**版本：** V0.1  
**状态：** 已完成早期 AkShare 优先验证；当前数据源方向调整为 TuShare 优先

# 1. 目录

| 路径 | 说明 |
|---|---|
| `backend/market_review/config.py` | 指数、周期、均线窗口和管道配置 |
| `backend/market_review/sources/akshare_source.py` | AkShare 补充数据源适配器 |
| `backend/market_review/sources/tushare_source.py` | TuShare 优先数据源适配器 |
| `backend/market_review/postgres_storage.py` | PostgreSQL 快照、增量序列、报告和 AI 初稿存储 |
| `backend/market_review/analytics.py` | 复盘总览 P0 派生计算和规则结论 |
| `backend/market_review/ai_analysis.py` | Vertex Gemini 解释层和报告初稿生成 |
| `backend/market_review/pipeline.py` | 采集、入库、计算、输出编排 |
| `backend/scripts/generate_market_overview.py` | 命令行生成入口 |

---

# 2. 运行方式

生成指定交易日总览：

```bash
python3 backend/scripts/generate_market_overview.py --trade-date 20260731 --start-date 20250101
```

开发调试时可以限制行业数量，减少外部接口调用时间：

```bash
python3 backend/scripts/generate_market_overview.py --trade-date 20260731 --start-date 20250101 --max-industries 5
```

# 5. 数据频度与增量规则

1. 前端读取总览和切换日期只访问 PostgreSQL，不触发 AkShare、Tushare、同花顺或 Gemini。
2. 建议每个交易日收盘后 16:10 执行一次数据生成任务。
3. 指数和行业日线首次运行写入历史区间；以后只请求数据库最新日期之后的数据。
4. 同一交易日重复生成时，默认复用已保存的指数、行业、市场广度和行业汇总。
5. 市场涨跌家数和行业当日汇总属于即时快照，只允许当日采集；历史缺失时直接报错，不能用当前快照冒充历史数据。
6. 每周报告复用当周已保存的数据，不重复下载完整历史。
7. `force_data_refresh=true` 只用于明确重抓当日数据；历史即时快照不支持强制重抓。

AI 使用“交易日 + 报告类型 + 输入摘要哈希 + 模型”识别缓存。数据和模型均未变化时直接复用；只有数据变化或 `force=true` 时才重新调用 Gemini。

# 6. AI 分析边界

规则计算层仍是事实和证据来源。Gemini 只负责生成系统初稿，包括：一句话总结、四时间尺度、指数结构与关键成分股表现、市场广度与成交、当日行业涨跌排名、前后期变化、冲突证据、后续观察和完整报告。V0.2 不再包含 A池/B池，也不生成“持续强势”等行业阶段标签。

AI 不联网补数据，不预测后市，不给出买卖建议。以下环境变量全部必需：

```text
VERTEXAI_PROJECT
VERTEXAI_LOCATION
VERTEX_MODEL
GOOGLE_APPLICATION_CREDENTIALS
```

任一变量缺失、凭证文件不存在或认证失败时，AI 生成直接报错，不切换其他模型，也不以规则文本伪装 AI 结果。

# 7. 限制

1. `ak.stock_zh_a_spot` 仅用于当日涨跌家数快照；历史涨跌家数、成交额、创 20 日新高/新低和站上 20/60 日线比例，使用已落库的 60 个交易日 `tushare.daily` 与 `tushare.adj_factor` 计算。
2. 首版行业口径是 AkShare 同花顺行业板块，不是申万一级行业。
3. 涨跌停口径直接使用 AkShare 涨停池和跌停池，不自行推算。
4. 跌停接口返回无字段空表时报告生成直接报错，不按 0 处理，也不生成“未知”占位。
5. 指数权重只用于确定成分范围；当前方向优先验证 TuShare 权限和质量，不满足时再按确认后的字段口径使用 AkShare。
6. 关键成分股名称和所属申万行业来自同花顺个股公司页，缺失时直接报错。
7. Tushare 数据按交易日存入 PostgreSQL，已有记录默认复用，不重复拉取全量历史。
8. Tushare 作为默认优先数据源；AkShare 作为缺口补充和交叉核对来源。
9. 自动调度尚未接入；当前由命令行或生成 API 触发收盘后任务。
