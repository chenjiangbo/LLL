# A-PreV2 AI 二次研究调用架构优化方案 V1.0

> **用途：交给 AI Coder 直接改造现有 AI 深度研究模块**
>
> 本文只解决一个问题：
>
> > **A-PreV2 技术选股后，AI 到底应该按照什么顺序、拿什么数据、用什么提示词，模拟一名有多年 A 股经验的交易者进行二次筛选。**
>
> 本文不重新设计 A-PreV2，也不重新设计 Q1/Q2/Q3/M1 的页面逻辑。
>
> 如果与现有《A-PreV2 候选股 AI 深度研究系统与 OpenAI-Base 集成设计与实现文档》中的“一次大 Prompt 完成全部判断”逻辑冲突，**以本文为准**。

---

# 1. 当前实现的问题

现有实现基本是：

```text
选中股票
↓
一次性读取：
- A-PreV2 技术分数/状态
- 公司数据
- 概念标签
- 市场画像
- 最近20日资金复盘
↓
拼成一个大 Prompt
↓
AI 一次完成：
- 判断市场主线
- 判断股票属于哪个主题
- 判断主题内地位
- 判断市场角色
- 最终给研究优先级
```

这个设计的问题是：

1. AI 在判断“应该和谁比”之前，没有真正的主题全市场数据。
2. 每只股票都重复读取完整历史复盘，浪费 Token。
3. 给 AI 太多程序已经加工过的结论，容易形成锚定。

---

# 2. 新的 AI 调用总流程

改成以下调用链：

```text
                ┌──────────────────────────┐
                │ 用户长期资金复盘数据库   │
                │ 近几周 / 几月 / 半年     │
                └────────────┬─────────────┘
                             ↓
                 AI-1：Market Memory
                 市场长期记忆 / 主题梳理
                             ↓
                  最近真实交易过的主题
                  + 每个主题的演化过程
                             ↓
                    【按日期缓存共享】

A-PreV2候选
↓
用户人工初筛
↓
选中股票
↓
AI-2：Theme Match
判断这只股票和 Market Memory 中
哪些主题真正相关
↓
        ┌───────────────────┴───────────────────┐
        ↓                                       ↓
命中近期/历史主题                         没有命中有效主题
        ↓                                       ↓
程序构建该主题全市场股票池                 不强行找主题
程序计算少量客观比较事实                   标记：
        ↓                               NO_ACTIVE_THEME_MATCH
Theme-relative Facts                         ↓
        └───────────────────┬───────────────────┘
                            ↓
                   AI-3：Final Research
                   最终二次研究
                            ↓
           高 / 中 / 低 / 证据不足
```

职责分工：

> **AI 决定“应该跟谁比”；程序负责“把比较事实算准确”；AI 再判断“这些事实意味着什么”。**

# 3. AI-1：Market Memory
## 建立“专业交易者的市场长期记忆”

这一步不为某一只股票服务。

它模拟的是：

> 一名长期每天复盘的专业交易者，对最近几个月市场曾经交易过什么、资金如何迁移、哪些故事反复出现的长期记忆。

### 输入来源

主要来源：

```text
用户复盘模块的每日资金复盘文字
```

系统至少支持：

```text
近20个交易日
近60个交易日
近120个交易日
```

推荐默认：

```text
近120个交易日
```

不要每次把半年原文全部重新发送。

需要维护一个：

```text
Market Memory Snapshot
```

结构：

```text
已有长期市场记忆
+
最近10~20个交易日较完整复盘
```

AI 根据新增复盘更新 Market Memory。

### Market Memory 要保存什么

不是主题分数，而是：

```text
最近真实被市场交易过的主题
每个主题大概什么时候出现
是否强化过
是否扩散过
是否分歧/衰减
后来有没有回流
当前大概是什么状态
它属于哪个更大的母题
```

状态建议：

```text
CURRENT_ACTIVE
RECENTLY_ACTIVE
DORMANT_BUT_TRADED
DECAYED
```

中文：

```text
当前活跃
近期活跃
曾经交易、目前沉寂
明显衰减
```

### 输出示例

```json
{
  "as_of_date": "2026-08-16",
  "lookback_sessions": 120,
  "themes": [
    {
      "canonical_name": "CPO/光通信",
      "aliases": ["CPO", "光模块", "光通信"],
      "status": "CURRENT_ACTIVE",
      "parent_theme": "AI算力",
      "first_seen_date": "2026-07-24",
      "last_active_date": "2026-08-15",
      "evolution_summary": "7月底开始异动，8月初加强，8/12明显成为主攻方向",
      "key_review_dates": ["2026-08-05", "2026-08-12"]
    }
  ]
}
```

不要输出：

```text
CPO = 92分
```

# 4. AI-1 提示词

## System Prompt

```text
你是一名长期跟踪中国 A 股资金风格、主题轮动和赚钱效应的资深市场分析人员。

你的任务不是预测明天哪个板块上涨，而是根据用户长期积累的每日资金复盘，建立一份“市场长期记忆”。

你要理解：
- 哪些主题过去几个月真正被资金交易过；
- 哪些只是单日异动；
- 一个主题什么时候开始出现、强化、扩散、分歧、衰减、回流；
- 不同主题之间的轮动和母题关系；
- 当前仍活跃、近期活跃、曾经活跃但沉寂、明显衰减的方向。

不要把主题转成0~100分。
不要机械统计关键词次数。
不要因为某个词一天出现一次就认定为主线。
需要结合连续多日复盘理解资金行为。

你是在维护一个专业交易者的“市场长期记忆”。

输出必须基于截至 as_of_date 已存在的复盘，不得使用未来信息。
```

## User Prompt

```text
查看日期：{as_of_date}

【已有 Market Memory】
{previous_market_memory}

【最近新增资金复盘】
{new_market_reviews}

请更新 Market Memory。

重点保留：
1. 最近真实被资金交易过的主题；
2. 每个主题的大致演化过程；
3. 当前状态；
4. 关键复盘日期；
5. 与更大母题之间的关系；
6. 对只有单日异动、持续性很差的方向明确区分。

请输出结构化 JSON + 一份适合人阅读的 Markdown 摘要。
```

# 5. AI-2：Theme Match
## 判断“这只股票真正应该和谁比较”

用户已经经过：

```text
A-PreV2
+
人工初筛
```

此时 AI-2 只负责一个问题：

> **这只股票与 Market Memory 中哪些主题真正有关？**

不要在这一调用里完成最终选股判断。

### 输入

给：

```text
股票名称 / 代码

M1 股票知识底库：
- 核心业务
- 重要业务
- 有布局的业务
- 同花顺概念
- 已验证主题关系

Q1最近季度基础数据（可简化）

Market Memory：
最近真实交易过的主题及演化
```

必要时允许网络搜索补充：

> 公司到底是否真正涉及某个主题。

### 不要给

```text
A-PreV2具体分数
Fundamental Score
Leadership Score
Market Profile Score
```

---

# 6. Theme Match 的两种结果

## 情况 A：命中 Market Memory 中的主题

例如：

```text
股票：中际旭创

PRIMARY：
CPO/光通信

SECONDARY：
AI算力
```

同时说明：

```text
公司和该主题的关系
为什么选择这个主题作为比较池
```

程序随后进入 Q2。

## 情况 B：没有命中近期/历史有效主题

例如：

```text
股票核心业务：
工业软件

Market Memory 最近半年：
没有明显工业软件行情
```

AI 输出：

```text
NO_ACTIVE_THEME_MATCH
```

并说明：

```text
该股票目前没有与近期真实交易过的市场主题形成明确共振。
```

注意：

> `NO_ACTIVE_THEME_MATCH` 不是负面结论。

对于 A-PreV2 早期反转股票，它可能意味着：

```text
新的潜在修复方向
尚未形成市场共识
个股独立变化
```

最终由 AI-3 判断。

# 7. AI-2 提示词

## System Prompt

```text
你是一名有多年 A 股经验的交易者。

你的任务非常单一：
判断这只股票在截至 as_of_date 的市场环境中，
真正应该和哪些“近期真实交易过的主题”放在一起研究。

你会得到：
1. Market Memory；
2. 股票业务/概念知识；
3. 少量公司事实。

不要因为同花顺有某个概念标签就自动匹配。
融资融券、沪股通、次新股等证券属性不是业务主题。

如果公司确实和某个活跃主题高度相关：
返回 PRIMARY / SECONDARY Theme。

如果近期 Market Memory 中没有合适主题：
明确返回 NO_ACTIVE_THEME_MATCH。

NO_ACTIVE_THEME_MATCH 不是负面结论。
对于早期反转股票，它可能意味着市场尚未形成主题共识。

不要在这里判断是否买入。
不要给股票研究优先级。
不要做最终二次研究。
```

```text
查看日期：{as_of_date}

【Market Memory】
{market_memory}

【股票基础信息】
{stock_basic_info}

【股票业务/概念知识】
{stock_knowledge_base}

【最近季度基础事实】
{quarterly_facts_brief}

请判断：
1. PRIMARY_ACTIVE_THEME
2. SECONDARY_ACTIVE_THEMES
3. NO_ACTIVE_THEME_MATCH 是否成立
4. 每个匹配的依据
5. 哪些同花顺标签不应作为当前比较主题
```

# 8. 程序 Q2：Theme-relative Facts
## AI 选好“和谁比”以后，程序只算客观事实

如果 AI-2 得到：

```text
PRIMARY_THEME = CPO/光通信
```

程序才：

```text
获取全市场 CPO/光通信成员
```

比较池必须是：

> **整个主题成员**

不是：

```text
A-PreV2候选
```

也不是：

```text
用户勾选的研究池
```

### 只提供少量辅助事实

至少：

```text
主题本轮观察起点
本轮以来个股涨幅
本轮主题内涨幅排名
首次明显启动日期（如果可靠）
近5日平均成交额
主题内成交额排名
```

示例：

```text
主题：CPO/光通信
本轮观察起点：2026-08-05
主题成员：54只

本股本轮涨幅：+21.3%
主题排名：2 / 54

首次明显启动：2026-08-06

近5日平均成交额：82亿
主题成交额排名：1 / 54
```

### 重要原则

最终 Prompt 中必须明确：

> 这些数据只是截至当前市场已经留下的客观痕迹，不是选股规则。

例如：

```text
排名靠前
```

不自动等价：

```text
未来更强
```

排名普通也不代表：

```text
不能成为补涨或新核心
```

# 9. AI-3：Final Research
## 最终二次研究

这一步模拟：

> **一名有多年经验的 A 股交易者，已经知道这只股票技术上通过初筛，现在要判断它是否值得进一步投入研究和交易注意力。**

这是整个 AI 系统最重要的一步。

---

# 10. AI-3 的主导思考顺序

AI 不应该按：

```text
技术分
+ 基本面分
+ 主题分
+ 资金分
```

加权。

而应该依次思考：

1. **最近市场的钱主要在哪里？**
2. **这只股票和这些钱真正有关系吗？**
3. **如果有关，这一轮市场已经怎样对待它？**
4. **如果无关，它有没有可能是尚未形成共识的新修复方向？**
5. **公司最近有没有值得市场重新定价的实际变化？**
6. **它是什么体量，资金可能用什么方式交易它？**
7. **技术已经过筛，现在实际位置怎样？**
8. **和其他候选相比，为什么值得优先花时间研究它？**

最终才形成：

```text
高 / 中 / 低 / 证据不足
```

amount

20日成交额中位数

# 12. AI-3 提示词

## System Prompt

```text
你是一名有多年中国 A 股实战经验的主观交易研究员。

你现在做的不是技术选股，也不是预测明天涨跌。

这只股票已经通过了一套独立的技术初筛。
你的任务是做“二次研究”，判断：
它是否值得在当前市场环境下被优先投入更多研究时间。

你的思考方式要接近真实专业交易者，而不是量化打分模型。

你需要综合理解：

1. 最近几个月市场真正交易过哪些主题，资金如何迁移；
2. 这只股票是否真正属于其中某个活跃或近期活跃主题；
3. 如果属于主题，市场截至目前已经如何对待它；
4. 如果不属于当前主题，它是否可能处于尚未形成市场共识的新修复方向；
5. 公司最近几个季度是否出现值得市场重新定价的实际变化；
6. 公司的业务和市场故事是否真实匹配；
7. 股票的市值、成交额和换手意味着它更可能以什么方式被资金交易；
8. 技术初筛之后，它当前实际位置是否仍值得继续研究；
9. 为什么资金可能选择它；
10. 为什么资金也可能不选择它。

重要规则：

- 不要使用加权打分思维。
- 不要因为某个指标排名高就自动给出高优先级。
- Theme-relative 数据只是参考证据，不是决策规则。
- 不要因为没有命中近期主线就自动判低。
- 对早期反转股票，“尚无主题共振”可能意味着市场还没有形成共识。
- 不要因为公司基本面不好就自动排除题材交易机会。
- 也不要因为有一个好消息就忽略明显反证。
- 以原始数据为主，不要依赖程序标签。
- 明确区分事实、推理和不确定性。
- 不得使用 as_of_date 之后的信息判断当时机会。
- 最终研究优先级只能是：高 / 中 / 低 / 证据不足。
- “高优先级”表示值得进一步研究，不等于买入建议。
```

# 14. 多股票调用时的性能设计

假设用户一次选：

```text
10只股票
```

正确结构：

```text
AI-1 Market Memory：
1次共享调用

AI-2 Theme Match：
10次轻量调用

程序 Theme-relative Facts：
只对命中主题的股票计算
同一主题池只构建一次

AI-3 Final Research：
10次独立调用
```

这样避免：

```text
10只股票重复发送半年复盘
```

# 18. 本次改造验收点

- [ ] Market Memory 不再每只股票重复生成
- [ ] Market Memory 支持至少近120个交易日的长期市场记忆
- [ ] Market Memory 不输出主题0~100分
- [ ] Theme Match 是独立 AI 步骤
- [ ] Theme Match 可以返回 NO_ACTIVE_THEME_MATCH
- [ ] NO_ACTIVE_THEME_MATCH 不自动导致低优先级
- [ ] 命中主题后程序才计算 Theme-relative Facts
- [ ] Theme 比较池使用全市场主题成员
- [ ] Theme-relative Facts 只作为 AI 辅助信息
- [ ] Final Research 不接收 A-PreV2 总分
- [ ] Final Research 主要接收基础技术事实
- [ ] Final Research 接收季度基础财务数据，而不是只接程序标签
- [ ] Final Research 接收原始 Market Profile 数据
- [ ] Final Research 同时分析“为什么会选它”和“为什么不会选它”
- [ ] AI 最终不使用加权总分
- [ ] 历史日期严格无未来信息

# 19. 最终设计哲学

这套 AI 调用不是为了：

> 让 AI 按一套机械规则替用户自动选股票。

而是尽量模拟：

> **一名长期每天复盘、记得最近几个月市场故事、又有多年 A 股经验的交易者，在技术初筛之后如何进一步缩小股票范围。**

职责分工：

```text
A-PreV2：
负责找到技术上值得看的股票

用户资金复盘：
构成长期市场记忆的原始素材

AI-1：
维护“最近市场交易过什么”的长期记忆

AI-2：
判断某只股票真正应该放到哪个市场故事里研究

程序：
把能够准确计算的主题内客观数据算出来

AI-3：
综合市场故事、公司事实、主题位置、市场画像和反证，
判断这只股票是否值得被进一步研究

用户：
最终决定是否交易
```

最终目标不是：

> “AI算出哪只股票分数最高。”

而是：

> **让 AI 像一个真正理解近期 A 股市场的人一样，帮助用户把几十只技术候选继续缩小到少数最值得研究的机会。**
