1. 核心功能不允许兜底。核心步骤失败就应报错，不能伪造成功结果。

## 2. 产品范围

当前单页应用有两个一级功能：

1. **复盘**
   - A 股市场复盘总览。
   - 指数、市场广度、行业涨跌、市场分类和 Gemini 系统初稿。
2. **自动选股**
   - 对股票和 ETF 计算 A/B/C 三类候选池。
   - A：长期下降后的潜在反转。
   - B：上涨趋势中的健康调整。
   - C：下降趋势中的短期反弹。
   - 候选分数不是上涨概率，也不是买入信号。

需求与口径文档位于 `docs/`。不需要阅读 `个人中期交易系统_后续ToDo_List_V0.1.md`，除非用户另行要求。

## 4. 数据源和口径

### 4.1 总原则

- AkShare 有稳定现成接口时优先 AkShare。
- AkShare 没有、质量不满足或自行聚合过于复杂时，再使用已确认的 Tushare 接口。
- 不允许运行时隐性切换数据源。
- 数据入 PostgreSQL 复用，日常只做增量。

### 4.2 复盘

- 指数日线：AkShare 腾讯指数历史。
- 当日市场涨跌家数：AkShare A 股快照。
- 涨停/跌停：AkShare 东方财富涨跌停池，直接取池内数量，不自行推算。
- 行业：AkShare 同花顺行业板块。
- 行业界面只显示当日涨幅前 10 和跌幅前 10。
- 不再生成“持续强势、低位修复、持续弱势、退潮”等行业阶段标签。旧需求文档中有这些名称，但当前数据不足以支撑可靠分类。
- 市场技术广度：严格使用 60 个交易日 `tushare.daily + tushare.adj_factor`。
- 计算指标：20 日新高/新低、站上 20/60 日线的家数和比例。历史不足或无可用标的时直接报错。

### 4.3 自动选股

- 股票名单：Tushare `stock_basic(list_status=L)`。
- ETF 名单：Tushare `fund_basic(market=E,status=L)`。
- 股票日线/复权/基本交易字段：`daily`、`adj_factor`、`daily_basic`。
- ETF 日线/复权：`fund_daily`、`fund_adj`。
- 规则集：`ABC_V1.0`。
- 默认 A/B/C 入池门槛均为 60 分。

## 5. 已实现功能

### 5.1 复盘页

- 按已保存交易日切换报告。
- 五大指数的时间尺度、内部广度和关键成分股。
- 指数卡可跳转东方财富 K 线页。
- 市场分类、当日行业涨跌前各 10。
- 市场广度：涨跌家数、涨跌停、新高新低、20/60 日线比例、成交变化。
- Gemini 分析会解释“指数方向与上涨家数是否背离”，并区分短期和中期广度。

### 5.2 自动选股页

- A/B/C/全部池切换。
- PostgreSQL 服务端分页，每页可选 25/50/100/200 条。
- 页码下拉、上一页、下一页。
- 最低分/最高分区间过滤。
- 代码、名称、阶段全量搜索，搜索由数据库执行，不是只搜当前页。
- 名称列固定为 170px，原因列获得更多空间。
- 列表没有独立纵向滚动条，只使用整页滚动。
- 顶部同时显示在册数、当日行情覆盖数、参与扫描数和筛选后候选数。

### 5.3 当前 API

- `GET /health`
- `GET /api/market-review/overview/latest`
- `GET /api/market-review/overview/{trade_date}`
- `POST /api/market-review/overview/generate`
- `POST /api/market-review/ai/generate`
- `GET /api/market-review/history`
- `GET /api/screening/latest`
- `GET /api/screening/{trade_date}`
- `GET /api/screening/history`
- `POST /api/screening/run`

## 7. 尚未解决的重要问题

### P0：候选率过高，需要与用户商量后调整规则

当前数据采集和统计算术没有少抓，但候选结果显著过多：

- 股票候选率：2486 / 5533 = 44.9%。
- ETF 候选率：398 / 2078 = 19.2%。
- 全部资产候选率：2884 / 7611 = 37.9%。
- A 池股票：1034，中位分 66，727 只低于 70 分。
- C 池股票：1154，中位分 74。

需求文档将“候选超过整个股票池 20%”视为异常检测情形。因此当前规则可能过宽，特别是 A/C 池。

**不要直接提高 60 分门槛或修改 A/C 规则。** 先向用户展示分数分布、各模块命中率和几组候选样本，再确认调整方案。

### P1：选股功能仍不完整

根据设计文档，仍缺少：

- 股票/ETF 独立 Tab 或资产类型过滤。
- A1/A2/A3、B1/B2/B3、C1/C2/C3 阶段过滤。
- 候选详情页和日 K 线。
- 人工关注、已阅、排除等界面流程。后端已有部分人工选择存储方法，前端未接入。
- 候选新入、升级、降级、重返等变化摘要。
- 候选数量异常告警的产品化呈现。

### P2：运行工程问题

- Next.js 配置了 `output: 'standalone'`，但目前使用 `next start` 运行，会有警告，但已验证可返回页面和静态资源。
- Next.js 检测到 `/Users/xipilabs/package-lock.json` 和项目内 `package-lock.json` 两个锁文件，会提示 workspace root 警告。不要擅自删用户的上层锁文件。
- 曾经使用 `next dev` 长时间运行后进程占用超过一个 CPU 核并卡死，页面表现为白屏。当前使用生产构建 + `next start` 保持稳定。
- 还没有收盘后自动调度。当前由 API 或命令行手工触发。
