# 交易系统前端现状说明（包含 TradePlan，供 UI 设计使用）

> 本文描述当前代码实际提供的页面和交互，不是新的设计方案。

## 1. 产品层级

TradePlan 位于“交易系统”一级功能下面，是交易系统的二级功能。

交易系统的二级功能包括：

- 交易总览
- 交易计划
- 交易执行
- 订单
- 持仓

交易设置通过交易系统公共 Header 的设置图标打开，不属于 TradePlan 页面内部内容。

## 2. 当前 TradePlan 页面结构

### 交易计划列表

默认进入列表模式。页面是浅色背景，中间为白色卡片，标题为“我的交易计划”。

标题右侧有两个图标按钮：刷新、新建（加号）。

卡片内部是表格，表头为：

| 表头 | 当前含义 |
|---|---|
| 股票 | 当前行实际展示动作序号和动作名称 |
| 状态 | Action Plan 状态 |
| 入场 / 风险参考 | 参考入场价 / 风险参考价 |
| 计划数量 | 计划数量 |
| 账户风险 | 计划风险占账户比例 |
| 操作 | 草稿编辑、Markdown 导出 |

列表数据通过 /api/trades 读取，再把每个 Trade 下的 plans 展开为表格行。

每组上方会显示：

    交易 300380 安硕信息    计划中

分组下方理论上显示：

    第 1 项    建仓
    第 2 项    加仓
    第 3 项    减仓
    第 4 项    清仓

但当前旧数据的 action_type 在数据库顶层，部分前端显示逻辑仍从 input_json.action_type 读取，因此现有数据可能看不到正确动作名称。

### 新建 / 编辑

点击右上角加号后进入新建模式。

页面是左右两栏：

    左侧：K 线区域
    右侧：交易计划表单和计算结果

左侧约占三分之二，右侧约占三分之一。

右侧表单标题为“交易计划”，右上角有返回列表图标。

底部三个按钮在同一行：确认计划、存草稿、导出。

## 3. 当前股票输入和 K 线交互

股票输入框位于右侧表单顶部，提示文字为：

    输入股票代码或名称

输入后调用市场股票建议接口，自动填充股票代码、股票名称和当前价格。

当前不是只取自选股，而是使用市场建议接口。

如果是策略筛选带入的股票，会显示选股来源、策略名称、策略阶段和日期，并自动生成交易逻辑文字。

K 线使用系统已有的 KLineModal 嵌入左侧，不是静态图片。

价格拾取交互：

1. 先聚焦右侧某个价格输入框；
2. 鼠标移动到左侧 K 线；
3. 点击价格位置；
4. 当前价格写入被聚焦的输入框。

## 4. 当前 OPEN 表单字段

当前新建表单实际上是 OPEN 建仓表单：

| 字段 | 是否必填 | 说明 |
|---|---:|---|
| 参考入场价 | 是 | 可从 K 线拾取 |
| 最高可接受价 | 是 | 可从 K 线拾取 |
| 风险参考价 | 是 | 可从 K 线拾取 |
| 本次风险比例 | 是 | UI 输入百分比，例如 0.80%，后端保存 0.008 |
| 目标方式 | 否 | 趋势跟踪 / 固定目标 |
| 目标价 | 固定目标时 | 固定目标价格 |
| 预期价格 | 趋势跟踪时 | 计算预期收益 R |
| 人工计划数量 | 否 | 留空使用系统建议 |
| 风险参考说明 | 否 | 多行文字 |
| 交易逻辑 | 否 | 多行文字或策略来源自动生成 |

当前新建表单没有让用户选择 OPEN / ADD / REDUCE / CLOSE，因为右上角加号只创建新的建仓计划。

## 5. 当前计算结果

### 账户未准备好

显示：

    无法计算建议仓位
    请先完成交易账户和风险规则配置。

不会把缺失账户数据伪装成 0 股。券商未连接不参与 TradePlan 计算准备条件。

### 交易计划摘要

显示最终计划数量或人工计划数量、预计投入、本次资金仓位、交易后总仓位。

### 风险

显示参考入场价、风险参考价、价格风险、风险预算、按风险参考价退出时的预计计划亏损，并提示跳空、滑点可能造成实际损失高于计划值。

### 仓位计算

显示风险预算允许、单只股票最大仓位允许、可用现金允许、账户总仓位允许、最终限制。

如果发生交易单位调整，会显示原始数量、按 A 股交易单位向下调整、最终数量。

### 收益 / 空间

固定目标模式显示目标价、潜在盈利、计划收益率和收益风险比。

趋势跟踪模式显示退出方式、1R / 2R / 3R、预期价格和预期收益 R。

### 最高买入价情景

最高可接受价高于参考入场价时，显示该价格下的建议数量、计划亏损、账户风险、资金仓位和交易后总仓位。

### 账户依据

显示当前账户净资产、可用现金、当前总仓位、默认单笔风险、单只最大仓位、账户最大总仓位。这些数据为只读账户上下文。

## 6. V2.0 后端已有但当前前端未完整呈现的模型

后端已经有 Trade、TradePlan、TradePlan action_type、TradePlan sequence_no、TradeLeg、TradePositionState、PositionRiskHistory、ExitRule。

动作类型：

- OPEN：建仓
- ADD：加仓
- REDUCE：减仓
- CLOSE：清仓

主要接口：

    GET  /api/trades
    GET  /api/trades/{trade_id}
    POST /api/trades/{trade_id}/add/calculate
    POST /api/trades/{trade_id}/add
    POST /api/trades/{trade_id}/reduce/calculate
    POST /api/trades/{trade_id}/reduce
    POST /api/trades/{trade_id}/close/calculate
    POST /api/trades/{trade_id}/close
    GET  /api/trades/{trade_id}/position-state
    GET  /api/trades/{trade_id}/risk-reference-history
    GET  /api/trades/{trade_id}/exit-rules
    POST /api/trades/{trade_id}/exit-rules
    PATCH /api/trades/{trade_id}/exit-rules/{rule_id}
    DELETE /api/trades/{trade_id}/exit-rules/{rule_id}

当前正式页面仍以 OPEN 建仓页面为主，ADD / REDUCE / CLOSE 还没有形成完整的正式主界面。

## 7. 交易执行页面当前关系

交易执行页面读取已确认或已就绪的 TradePlan。

- OPEN / ADD 创建买入执行计划
- REDUCE / CLOSE 创建卖出执行计划
- 执行数量必须等于计划数量
- 买入检查最高可接受价
- 卖出不套用买入最高价限制
- 券商未连接时只保存执行意图，不生成虚假订单或成交

交易执行当前仍是独立工作台，还没有完整嵌入 Trade 详情时间线。

## 9. 当前视觉和交互特征

- 使用交易系统公共 Header
- 浅色背景、白色卡片
- TradePlan 页面卡片相对其他交易页面更大、更圆、更松散
- 右侧表单字段以两列排列
- 使用 lucide-react 图标
- 图标按钮带鼠标悬停提示
- 错误消息使用右下角浮动提示
- 新建页左侧为 K 线，右侧为表单
- 当前没有独立的 Trade Detail 正式页面
- 当前没有完整的动作类型选择界面
- 当前没有在一张正式页面中完整展示 Trade、动作计划、订单、成交和持仓的层级关系

## 10. 设计时需要保留的功能约束

- K 线必须保留系统现有组件，不能改成静态图片
- 价格拾取必须写入当前聚焦的价格字段
- 风险比例用户界面显示百分比，不显示 0.008
- 金额使用千位分隔
- 内部枚举不能直接展示给用户
- 券商未连接不能阻止规划账户阶段的 TradePlan 计算
- QMT、实盘和虚拟盘委托不在当前前端设计范围内

## 11. 交易系统公共界面

交易系统由 TradingSystemShell 统一承载，不是独立的一套 Header。

左侧为固定的窄竖向二级导航，只有图标按钮，鼠标悬停显示提示：

- 交易总览
- 交易计划
- 交易执行
- 订单
- 持仓

公共顶部 Header 右侧目前有券商连接状态图标、暂停 / 恢复交易执行状态图标、交易设置图标和用户图标。

券商连接状态和暂停状态属于交易系统公共状态，不属于某一个二级页面。

## 12. 交易总览页面现状

页面通过交易总览、Trade 聚合、执行计划和订单接口读取数据。

当前布局从上到下为：

### 账户摘要

上方两列卡片显示总资产、今日盈亏、累计盈亏、账户类型、可用现金、总仓位进度条和持仓市值。

### 统计卡片

显示当前持仓数量、活动交易计划数量、活动执行计划数量和未完成委托数量。

### 规划持仓

下方表格显示证券、数量 / 可卖数量、成本 / 现价、市值、盈亏、风险参考价和操作图标。

操作图标当前包括创建计划、调整风险参考和更多，但部分操作尚未接入完整动作页面。

当前总览已经读取 Trade 聚合数据统计活动计划，但界面还没有完整展示 Trade 当前风险、最近动作和时间线。

## 13. 交易执行页面现状

页面读取执行计划、券商连接状态以及 READY / ARMED 状态的 TradePlan。

券商未连接时，页面显示：

    券商未连接
    当前可以保存并启用执行意图，但不会创建虚假订单或成交记录。

该页面不负责建立 TradePlan，只负责把已确认的动作计划转成 ExecutionPlan。

待执行交易计划区域显示股票、计划数量、参考价格、最高可接受价和创建执行按钮。

创建执行计划时，OPEN / ADD 使用买入方向，REDUCE / CLOSE 使用卖出方向。

执行计划编辑区当前支持限价委托、持续限价、价格触发、价格区间触发和有效期。

执行计划卡片当前显示股票、买入 / 卖出、执行方式、目标数量、执行规则、已成交 / 目标数量、剩余数量、当前状态，以及暂停、继续、取消图标。

当前执行页面仍按 ExecutionPlan 卡片展示，尚未在视觉上嵌入所属 Trade 和动作时间线。

## 14. 订单页面现状

订单页面读取订单接口，使用表格展示时间、证券、买入 / 卖出、订单类型、价格、数量、成交数量和比例、订单状态、订单编号及撤单操作。

订单状态会翻译成中文，例如等待发送、已发送、已接受、部分成交、全部成交、已撤单和已拒绝。

当前订单页面没有显示所属 Trade、所属 Action Plan、OPEN / ADD / REDUCE / CLOSE、对应风险预算或成交归因 TradeLeg。

因此它目前仍是传统订单记录表，而不是 Trade 生命周期中的订单节点。

## 15. 持仓页面现状

持仓页面读取规划账户和持仓。

顶部显示总资产、持仓市值、可用现金和总仓位。

持仓表格显示证券名称和代码、总数量 / 可卖数量、平均成本 / 当前价格、市值、浮动盈亏、当前风险参考价，以及创建计划、调整风险参考、更多图标。

当前持仓页面没有显示所属 Trade、Trade 类型、Trade 状态、OPEN / ADD 交易腿、当前本金计划风险、当前利润回吐风险或 Trade 风险预算使用情况。

因此它目前仍是按证券聚合的账户持仓表，而不是按 Trade 管理持仓。

## 16. 交易设置页面现状

交易设置通过公共 Header 的设置图标打开，是一个弹出式设置窗口，不应自动切换到交易系统二级页面。

设置窗口当前有左侧导航：账户管理、风险控制规则、券商连接、数据管理。

账户管理包括账户名称、账户类型、账户状态、账户编号、币种、净资产、现金和可用现金。

风险控制规则包括默认单笔风险比例、最大单笔风险比例、单只股票最大仓位、账户最大总仓位和最低现金比例等参数。

券商连接页面属于连接配置，不应成为 TradePlan 计算的前置条件。

数据管理是交易设置窗口中与行情 / 筛选数据相关的附加区域，不属于 TradePlan 核心页面。

## 17. 五个页面之间的当前数据关系

当前后端关系已经升级为：

    Trade
      └── TradePlan
            └── ExecutionPlan
                  └── Order
                        └── Fill

同时：

    Trade
      ├── TradeLeg
      ├── TradePositionState
      ├── PositionRiskHistory
      └── ExitRule

当前前端实际呈现仍然是：

    交易总览：账户和持仓摘要
    交易计划：OPEN 表单和计划列表
    交易执行：ExecutionPlan 工作台
    订单：订单表格
    持仓：证券聚合持仓表

也就是说，后端已经是围绕 Trade 的生命周期模型，但前端仍然是多个相互独立的功能页面。这正是本次需要交给 UI 设计器重新规划的重点。

## 18. 当前前端改造的总体事实

需要一起重新设计的范围是：

- 交易总览：加入 Trade 级风险与最近动作
- 交易计划：从 OPEN 表单升级为 Trade 生命周期入口
- 交易执行：明确属于哪个 Trade 和哪个动作计划
- 订单：显示 Trade、动作计划和成交进度
- 持仓：显示 Trade、TradeLeg、风险和 T+1
- 交易设置：继续作为公共弹窗，提供 TradePlan 所需账户风险依据

QMT、实盘和虚拟盘下单界面不在本次 UI 设计范围内。
