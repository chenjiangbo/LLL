# 交易系统前端 UI / UX 全量重构开发计划 V1.0

## 目标

在不改变现有 React / Next.js 页面体系、一级导航和左侧二级导航样式的前提下，完成交易系统除“配置”外 12 个原型页面的复刻、账号上下文隔离、真实接口绑定和页面间业务跳转。券商对接实现不在本计划修改范围内。

## 执行顺序

1. **基础上下文**：在交易系统一级导航选择交易账号；所有交易查询和写操作显式携带 `account_id`；账号切换时清空旧页面状态并重新加载；实现账号级暂停 / 恢复和撤销未成交订单。
2. **原型页面载入**：按 `public/prototype-pages` 载入 12 个非配置原型 HTML，第三方资源本地化，保留现有外层导航和页面框架，不引入第二套技术框架。
3. **查询页面**：接入总览、交易列表、Trade 详情、执行计划、订单、持仓的账户资产、Trade、TradePlan、ExecutionPlan、Order、Fill、Position、风险和退出规则字段；无数据、失败和权限状态分别展示。
4. **交易动作**：接入建仓、加仓、减仓、清仓的输入字段、计算接口、确认接口和服务端刷新；接入风险参考新增、历史查询；接入退出规则新增、修改、删除。
5. **执行闭环**：接入 TradePlan → ExecutionPlan → Order → Fill 的创建、启用、暂停、恢复、取消、撤单、详情和成交回报；所有成功写操作重新读取服务端状态。
6. **关系跳转**：总览 / 交易 / 持仓进入 Trade 详情，详情进入各交易动作和风险 / 退出规则，TradePlan 创建 ExecutionPlan，ExecutionPlan 进入订单，订单查看成交回报；跳转始终保留当前账号和 Trade 上下文。
7. **验收**：逐页检查 DOM / 样式 / 本地资源 / 字段 / 空态 / 失败态 / 弹窗 / 表单校验 / 跳转；执行 TypeScript 构建、接口回归、账号隔离检查和浏览器运行态检查。

## 验收门槛

- 12 个重构页面不显示原型演示数据；展示值来自真实接口或当前用户输入。
- 所有交易请求显式携带 `account_id`，账号 A 数据不出现在账号 B 页面。
- 核心写操作失败时显示错误，不提前修改页面状态；成功后重新读取服务端状态。
- 计算、交易、订单、风险和成交链路不使用 mock、fallback、抽样或静默跳过。
- 配置页保持现有实现；不修改券商对接代码。
- `npm run build`、接口回归和运行态关键路径检查通过。
