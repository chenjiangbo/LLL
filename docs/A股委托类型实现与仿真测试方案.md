## 本次测试要回答的问题

1. 界面选择的委托类型，是否原样经过主后端和 Broker Node，最终由 Windows Agent 传给 GM 的 `order_volume`。
2. 券商仿真柜台是否接受该委托类型，并返回订单状态；若拒绝，保存柜台的原始错误信息。
3. “立即提交”“达到触发价格时提交”“进入价格区间时提交”是否按预期等待或生成委托。
4. 可选开始执行时间是否会让计划先等待，到达设定时间后才开始执行。

本次只测仿真账号；不把 SDK 有对应枚举、Node 收到命令或 HTTP 返回成功算作柜台通过。

## 明天的执行步骤

### 1. 开盘前准备

1. 在界面选择名称明确标为“交易时段”的仿真账号；核对账号、策略实例及 Broker Node 对应关系。历史记录中的 `account_id=3` 是旧快照，仅作查找线索，开始前以当前界面和账号接口返回为准。
2. 确认 Agent、Node、主后端的交易连接和行情订阅均在线；确认订单、成交查询可用。
3. 检查账户的单笔最大金额设置，并确认测试证券每 100 股的参考金额低于该上限。每次只提交一笔，上一笔状态明确后再继续。
4. 选一只当前可交易、流动性较好的上交所股票和一只深交所股票；测试数量按 100 股起步，实际价格和账户规则必须满足计划计算结果。
5. 在连续竞价期间操作，建议 09:35–11:15 或 13:05–14:45，避开集合竞价与收盘前时段。

### 2. 先验证两个市场的限价完整链路

先按第 3 步矩阵完成上交所和深交所的限价样本；这两笔同时作为两个市场的完整链路基准，不要重复下单。逐笔核对：

- 页面显示的委托类型、方向、数量、委托价；
- TradePlan、ExecutionPlan 和本地 Order 保存的类型与价格；
- Broker Node 命令 ID、请求内容和处理状态；
- Agent 实际传给 `order_volume` 的 GM `OrderType_*` 常量及参数；
- 国投客户端/查询接口的券商订单号、状态、委托量、成交量和成交价；
- 主系统订单、成交、持仓及现金是否与柜台结果一致。

有未成交委托时，先核对并撤销，等柜台返回最终状态后再继续。收到明确拒单时记录原始错误码和消息；没有券商订单号、拒单回报或最终状态时，标记为链路未完成并查日志，不能算通过。

若委托被柜台接受但仿真盘口未出现部分成交、余量撤销或转限价，只能记为“报单链路通过、撮合语义未覆盖”。不人为伪造盘口或伪造成交来填结果。出现仍在活动状态的委托时先按正常撤单链路清理并确认柜台终态。

### 4. 验证三种提交时机

这些是执行计划何时提交委托，与“委托类型”是两个独立设置。使用普通限价、每次 100 股：

1. **立即提交**：启用后检查执行器是否立即创建并提交一笔订单。
2. **达到触发价格时提交**：先选一个尚未满足的买入触发价，确认计划处于等待且没有订单；等真实行情满足“买入最新价小于或等于触发价”后，确认只生成一笔订单。若当天行情没触发，记录“等待分支通过、触发分支未覆盖”，不要人为改行情。
3. **进入价格区间时提交**：确认真实最新价在设定区间外时没有订单；价格进入区间后确认只生成一笔订单。若行情没进入区间，同样记录为未覆盖。

条件触发必须看到真实、持续更新的行情（`FRESH`）；无新 Tick、过期 Tick 或连接中断时应显示明确等待/阻断原因，不可据此判定为已触发。

### 5. 验证可选开始时间

1. 选择“按设定时间执行”，设为当前时间之后约 1 分钟；提交前确认显示的时区和时间正确。
2. 开始时间到达前，检查没有生成本地订单，也没有发出 Node 下单命令。
3. 到达设定时间后，检查执行器启动并完成一次限价委托链路。
4. 再选“立即执行”，确认它忽略填写的开始时间并立即启动；若界面当前会清空该时间，则记录界面行为。

若到点后执行计划仍处于等待，先查看 API 保存的 `valid_from`、执行器状态原因、Agent/Node 状态与日志，不能只凭按钮提示判断成功。

## 单笔最大金额与成交价格

“单笔最大金额”在创建交易动作计划时，按计划参考价和计划数量计算并限制可计划数量。执行阶段选择委托类型时不再根据委托请求价格重复核验计划金额；市价委托按交易所契约传价（沪市保护限价，深市不传价格字段），成交价格与计划参考价之间的滑点属于成交结果。

明天需要核对两点：计划计算对超过单笔最大金额的手动数量明确报错；计划金额未超上限时，选择深交所市价类型能通过主后端并以无价格字段进入 Node。柜台回报中的实际成交价和金额单独记录，不据此倒推为计划金额校验失败。

## 通过标准与记录

- **端到端通过**：从界面选择到 Agent 的 GM 枚举一致，且查到券商订单号及券商回报；主系统订单/成交状态能与柜台核对。
- **柜台拒绝**：链路必须能定位到柜台并记录原始拒绝码/原因；该委托类型对当前账号不算可用通过。
- **链路失败**：命令未被消费、无 GM 调用证据、无券商订单号且无明确拒单回报，记失败并按故障点修复后重测。
- **撮合语义未覆盖**：柜台接受了委托，但当时盘口没有触发部分成交/撤余量/转限价等情形，不能据此宣称该语义已实证。
- 每项记录操作时间、账号名称、证券代码、类型、数量、Node 命令 ID、GM 枚举、券商订单号、原始回报、成交/剩余数量、主系统订单 ID 和最终结论。
